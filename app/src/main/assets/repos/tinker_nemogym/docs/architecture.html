tinker-nemogym Architecture

Bridge between NVIDIA NeMo-Gym RL environments and Thinking Machines Tinker — 3-process layout, hot-swap sampling client

Runtime architecture (one RL step)

Architectural parity: tinker-atropos ↔ tinker-nemogym

Key implementation contracts

NeMo-Gym contract (/run)

  • • Request: BaseRunRequest { responses_create_params, extras }
  • • Response: BaseVerifyResponse { reward, response, …benchmark }
  • • Model slot must subclass SimpleResponsesAPIModel
  • • Adding TokenIDLogProbMixin attaches prompt_token_ids, generation_token_ids, generation_log_probs
  • • Reward: ResourcesServer.verify() returns 0.0–1.0
  • • Multi-turn: agent's internal tool loop handles it — we only see the final rollout

Datum contract (Tinker)

  • • ModelInput.from_ints(all_tokens[:-1])
  • • target_tokens = all_tokens[1:], dtype int64
  • • advantages: float32, 0 on prompt, adv on response
  • • logprobs: float32, 1.0 sentinel on prompt, observed on response
  • • loss_fn="importance_sampling" — server-side string
  • • Alternative loss_fns: cross_entropy, ppo, cispo, dro

Hot-swap pattern

  • • Module-global _current_sampling_client behind threading.Lock
  • • save_weights_and_get_sampling_client_async() produces a fresh client per step
  • • set_sampling_client(new) atomically updates the global
  • • In-flight requests may still use step-N client — acceptable for MVP
  • • Never reuse a sampling client after a training step (verified in both refs)

Rollout concurrency

  • • rollout_group: asyncio.gather(*[_call_once(...) for _ in range(group_size)])
  • • rollout_batch: gather across prompts too (problems × groups fully parallel)
  • • Pipeline fwd_bwd + optim: enqueue both BEFORE awaiting
  • • FailFast vs RetryOnFailure: start with FailFast; switch if flaky envs
  • • Drop constant-reward groups (all zero advantage = no gradient)

Risks & gotchas

  • • Tokenizer mismatch between nemo-gym agent and Tinker base_model → shift corruption
  • • Special tokens stripped from decoded text but present in token_ids (Tinker issue #90)
  • • Uvicorn-in-thread with separate asyncio.run — possible loop collision; fallback: subprocess
  • • Weight-swap atomicity: rare stale-client window (ok for MVP)
  • • Python 3.12 hard requirement from nemo-gym
  • • vllm_model path unused — we fully replace the model slot
